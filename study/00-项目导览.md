# 00. 项目导览

> 阶段:主线 | 前置:无

在读任何代码之前,先建立全局认知。目标:能说清「Pi 是什么 / monorepo 怎么组织 / 怎么构建测试」。

## 学习目标

- 知道 Pi 是什么、解决什么问题
- 看懂 monorepo 的包划分与依赖方向
- 掌握 build / check / test / run 四类命令的分工与**坑**
- 知道 `AGENTS.md` 是规则权威,CLAUDE.md / CONTRIBUTING.md 各管什么

## 关键文件(先读这些)

- `README.md` —— 项目门面,包清单、权限与容器化、供应链加固概述
- `AGENTS.md` —— **规则权威**(风格、git、依赖、测试、发版),任何改动前必读
- `CONTRIBUTING.md` —— 贡献门禁、质量标准、issue/PR 流程
- `CLAUDE.md` —— 架构速览 + 关键规则索引(给 Claude Code 用,也可作你的快速索引)
- `package.json` —— 看 `workspaces`、`scripts`(尤其 `build` 的依赖顺序链)、`engines`
- `biome.json` / `tsconfig.base.json` —— 格式(Tab 宽度 3 / 行宽 120)与「可擦除 TS 语法」约束

## 核心概念

- **monorepo + workspaces**:`packages/*` 与若干 `examples/extensions/*` 都是 workspace 包。跨包用 `@earendil-works/pi-*` 名字互相 import。
- **构建有顺序**:根 `build` 脚本是一条依赖链 —— `tui → telemetry → ai → agent → sqlite-node → protocol → client → server → coding-agent`。
- **可擦除 TS(Node strip-only 模式)**:`erasableSyntaxOnly: true`,禁止 `enum`/`namespace`/参数属性/`import =`/`export =` 等。改代码要遵守。
- **禁止 inline import**:不能用 `await import()`、`import("pkg").Type`。只能顶层 import。

## 建议阅读顺序 / 动手练习

1. 通读 `README.md`,对照表格认全所有包。
2. 读 `AGENTS.md` 全文(尤其 Conversational Style / Code Quality / Commands / Git 四节)。
3. 读 `CLAUDE.md` 的「Architecture」一节。
4. 跑 `./pi-test.sh`,实际启动一次 `pi`,体验交互式模式。
5. 翻一遍根目录 `scripts/`,知道有哪些构建/发版/校验脚本(不用细读)。
